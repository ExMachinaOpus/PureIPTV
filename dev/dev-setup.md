# Development setup

## Toolchain

- Android SDK at `~/Android/Sdk` (`local.properties` points there; not committed).
- No system JDK needed: Gradle downloads and pins JDK 21 (`gradle/gradle-daemon-jvm.properties`).
- Android Studio is optional; open the project root.

## Emulators

| AVD | Image | Why |
|---|---|---|
| `PureIPTV_GoogleTV_API34` | Google TV, Android 14, 1080p | Same OS level as the Google TV Streamer |
| `PureIPTV_Phone_API37` | Pixel 8, Android 17, plain AOSP (no Play/Google services) | Current phone, lightest image; the app needs no Google services |

```
scripts/dev.sh emu tv          # window; arrow keys / Enter / Esc act as the remote
scripts/dev.sh emu phone
scripts/dev.sh run             # build + install + launch on the running device
```

Recreate them if needed:
```
sdkmanager "emulator" "system-images;android-34;google-tv;x86" "system-images;android-37.0;default;x86_64"
avdmanager create avd -n PureIPTV_GoogleTV_API34 -k "system-images;android-34;google-tv;x86" -d tv_1080p
avdmanager create avd -n PureIPTV_Phone_API37 -k "system-images;android-37.0;default;x86_64" -d pixel_8
# then in each ~/.android/avd/<name>.avd/config.ini:
#   hw.ramSize=2048  vm.heapSize=256M  hw.gpu.mode=host  hw.keyboard=yes
```

## Fake provider (test data)

`python3 scripts/fake-provider.py` serves a fake Xtream panel and an M3U with an XMLTV guide on port 8765.
Every channel, title, plot, logo, poster and video is invented or generated by the script, so its content
can be shown in store screenshots. It needs `ffmpeg` and Pillow; the first start renders the videos and
pictures into `build/fake-media/` (a few minutes), later starts reuse them. One stream is dead on purpose
(failover), one channel is offline, one entry is a separator and one category is adult. A film and a
series also have a 4K copy (versions); `FAKE_DEAD=1009,90201` (stream ids) makes those copies refuse
connections, for a picked version that stopped working. From an emulator:

- Playlist link: `http://10.0.2.2:8765/playlist.m3u`
- Server and login: `http://10.0.2.2:8765`, user `demo`, password `demo`

Never put a real provider's playlist or login in the repo; use `fixtures-private/` (gitignored).

## Measuring performance

Debuggable builds run several times slower on ART, so performance budgets (AGENTS.md rule 5) are
measured with the `benchmark` build type: release code (R8, not debuggable), debug signing, installs
next to the debug app as `app.pureiptv.bench`.

```
./gradlew :app:assembleBenchmark
adb install -r app/build/outputs/apk/benchmark/app-benchmark.apk
adb logcat -s PureImport:I        # "import source=… live=… in … ms" after each import
```

`http://10.0.2.2:8765/big.m3u?n=50000` on the fake provider is a 50k-entry playlist. Reference: on the
Google TV emulator a 50k import takes ~3 s in the benchmark build (~15–28 s in a debug build).
Its guide (`/bigguide.xml?n=…`, linked from the playlist) has 45-minute programmes on every channel for
3 days (~150 MB for 50k entries): `adb logcat -s PureImport:I PureSearch:I` shows guide import and
search timings.

## Dependency verification

Every downloaded dependency and plugin is checked against `gradle/verification-metadata.xml`
(SHA-256), so a tampered or swapped artifact fails the build instead of ending up in the app.
After changing a version in `gradle/libs.versions.toml`, or when a build fails with "Dependency
verification failed", regenerate the file and review the diff before committing it:

```
./gradlew --write-verification-metadata sha256 help test lint assembleDebug assembleRelease assembleBenchmark
```

The Gradle distribution itself is pinned by `distributionSha256Sum` in
`gradle/wrapper/gradle-wrapper.properties`; update it together with `distributionUrl` (the checksum
is published next to each distribution as `<file>.zip.sha256`).

## Release build

`scripts/dev.sh release [serial]` builds the production app (R8, not debuggable, release-signed) and
installs it as "PureIPTV" (`app.pureiptv`), next to "PureIPTV debug" and "PureIPTV bench". It has its own
data: add the source once. Use it to judge how the app really feels; debug builds are much slower.

Signing comes from `keystore.properties` in the project root (git-ignored):

```
storeFile=/absolute/path/to/release.keystore
storePassword=…
keyAlias=…
keyPassword=…
```

Create a key once with `keytool -genkeypair -keystore <file> -storetype PKCS12 -alias <alias> -keyalg RSA
-keysize 4096 -validity 36500`. Keep the keystore and its password backed up outside the repo: updates
only install over an app signed with the same key. Without the file, `assembleRelease` builds an unsigned APK.

The release app isn't debuggable, so `adb run-as` can't reach its data. To move user data into it (e.g.
favourites from a debug install), build `assembleRelease -PdebuggableRelease` (same app and key, but
debuggable), install it over the release app (data is kept), force-stop it, edit `databases/user.db`
via `run-as` (remove `user.db-wal`/`-shm` after replacing the file), then install the normal release over it.

## Adding your own source without typing

Put it in `fixtures-private/source.properties` (git-ignored): `link=<playlist URL>`, or `server=`,
`username=`, `password=`. Open "Set up from your phone" on the device and run
`scripts/send-source.py <address shown on the TV>`. It posts the form like a phone would and never prints
the file's contents. For an emulator, forward the port first: `adb forward tcp:<port> tcp:<port>` and use
`http://127.0.0.1:<port>/<token>`.

## "Set up Google TV" screen on the emulator

The Google TV home screen asks for a Google account and keeps asking after "Cancel". Ignore it: the
app doesn't need an account. `scripts/dev.sh emu tv` opens PureIPTV directly after boot (if installed),
and `scripts/dev.sh run` installs and opens it. The remote keys then go to the app.

## Emulator clock

`scripts/dev.sh emu` sets the emulator to this machine's time zone and a 24-hour clock (the image boots
in GMT). The clock itself can drift after the host sleeps; restarting the emulator fixes it. If the
emulator always cold-boots without quick-boot snapshots: a snapshot saved after the host had slept
got corrupted once and made every later start hang. If a start still hangs, run `scripts/dev.sh stop`
(also frees the Gradle daemon's memory) and start again.

## Keyboard in the emulator window

Arrow keys = D-pad, Enter = OK, **Backspace** (or the emulator's Ctrl+Backspace / ◁ button) = Back.
The emulator window does not forward Esc. Debug builds log every key the app receives:
`adb logcat -s PureKeys:D`.

## Memory budget

Target: a build plus one emulator fits on a 16 GB machine that is also running a desktop and browser.

| Item | Budget |
|---|---|
| One emulator (2 GB guest RAM + overhead) | ~2.5–3 GB |
| Gradle daemon (Kotlin compiles in-process, see `gradle.properties`) | ≤ 2.5 GB |

- **Only one emulator at a time.** `scripts/dev.sh emu` stops any running emulator first.
- `scripts/dev.sh stop` frees everything (emulators + Gradle daemon). The daemon also exits after 15 min idle.
- AVD RAM is set in `~/.android/avd/<name>.avd/config.ini` (`hw.ramSize=2048`); keep it at 2048.
- The headless emulator build (`--headless`) crashes on some Linux hosts (emulator 37.2); use the windowed one if it does.

## Google TV Streamer (real device, over Wi-Fi)

One-time:
1. Settings → System → About → select **Android TV OS build** 7 times (developer mode).
2. Settings → System → Developer options → **Wireless debugging** on.
3. Wireless debugging → **Pair device with pairing code**, then on the computer:
   `adb pair <ip>:<pair-port> <code>`
4. Give the Streamer a fixed IP (DHCP reservation in the router).

Each session: `scripts/dev.sh connect <ip>:<port>` (port shown on the Wireless debugging screen; it can
change after a reboot), then `scripts/dev.sh run <ip>:<port>`. The connect port is not the pairing port;
`adb mdns services` lists it (`_adb-tls-connect`). `run` installs only on the device given.

The Streamer's USB-C port is power only; Wi-Fi is the only debug connection.
